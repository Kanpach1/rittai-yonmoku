## 2026-10-08 着地音の聞き比べ(試作 A / B1 / B2 / B3 と今の音)

- **日付**: 2026-10-08
- **対象バージョン / commit**: 8bc749f(ゲーム本体は変更なし)
- **仮説または目的**: 起動演出と通常着手の「コトッ」に使う音を決める
- **変更内容**: `tools/sound-lab.html` を追加。試作音は `Inbox/KKT_Sound_Lab_B/`(git管理外)から読む
- **検証方法**: 名前を伏せ、並び順をランダムにし、最初の180msのRMSで音量を揃えて、1回と3回連続で聞き比べる。同じ端末・同じ音量で
- **結果**: ユーザーから「Claudeの好みで採用してよい」との指示。Claudeは試聴できないため、制作依頼の基準に照らして波形を数値で比較した(エネルギーの90%が出尽くす時間 / 周波数帯ごとのエネルギー比)
  - A: 57ms / 100-400Hz 77%・400Hz-1kHz 18%・1-2kHz 4%(乾いていて胴鳴りが短い)
  - B1: 97ms / 52%・37%・10%(帯域の釣り合いが最も良い)
  - B2: 116ms / 48%・49%・2%(1-2kHzが薄く輪郭が出にくい)
  - B3: 75ms / 8%・85%・6%(中域に偏る)
  - いずれも100Hz以下はほぼ0、2-5kHzは1%未満
- **判断**: B1_balanced を採用し、ゲームの着地音に組み込んだ(毎回ピッチ±0.5%、音量±0.5dB程度の揺らぎ。`?sound=legacy` で従来の音)。iPhone のスピーカーは低域が出にくく、B1は100-400Hzが半分を占めるため、実機のスピーカーで軽く聞こえないかを要確認
- **次の課題**: 選んだ音で、実際の盤の上で映像と合わせて確かめる

## 2026-10-08 着地音を v2(A / B / C、段ごと4変奏)に切り替え

- **日付**: 2026-10-08
- **対象バージョン / commit**: 592f5b4 の次(未コミット)
- **仮説または目的**: 制作依頼(A Reality / B Ideal Physics / C Boundary)に沿った v2 を、実機で盤の映像と同期させて比べる
- **変更内容**: 標準を v2 の C(4段×4変奏)にして index.html に埋め込み。`?sound=A` / `B` は `Inbox/rittai4_koto_v2/` から読む(ローカルサーバー経由のみ)。`?sound=B1` は前の試作、`?sound=legacy` は従来の合成音。音量は案ごとの共通係数で1段目を従来音に揃え(A 2.55、B・C 2.69)、段ごとの強弱は素材のまま。変奏は直前と同じものを避けて選ぶ。v2 使用時は通常着手の短い合成余韻を足さない(C の尾部に任せる)。起動と決着の長い余韻は従来どおり
- **検証方法**: 実機で A / B / C を切り替え、同じ局面で着手して比べる。README の手順(ランダム順、B と C を伏せて比較、16回・50回の反復、映像との同期)
- **結果**: (実機で試したあとに記入)
- **判断**: 標準を C にしたのは、リリースノートの「Bを基準、Cを最終候補」に従ったため(ユーザーの確定ではない)
- **次の課題**: C の尾部が電子音と分かるなら弱めるか削除。起動・決着用の長い余韻は未制作

## 2026-10-08 着地音を合成の scale(盤/玉 × 段ごとの五音音階)に切り替え

- **日付**: 2026-10-08
- **対象バージョン / commit**: 14e506f の次(未コミット)
- **仮説または目的**: v2 の素材より legacy の合成音が好み(短くて軽い・透明な余韻・ちょうどよい作り物感)。その良さを残し、要件 U-3「段と玉の重なりで変わる」「専用の音」を満たす
- **変更内容**: 標準を `scale` に(素材は読み込まない。`?sound=C` / `A` / `B` / `B1` / `legacy` は比較用に残す)
  - 接触: 盤(1段目)=低めで丸い「コトッ」、玉の上(2段目以上)=高めで硬い「カチッ」(高域の短いノイズを足す)
  - 余韻: 段ごとに G の五音音階(ソ392・ラ440・シ494・レ587Hz)。高い音ほど少し小さく。白黒は従来どおり warm / bright
  - 最強AIが勝ちを読み切った(探索の評価 > WIN−200)最初の1手だけ、余韻に +0.6% ずれた音を重ねて揺らす(1局に1回)。共有メモ §22 の例外としてユーザーが決定
  - 参考: Peggle 2(当たるたびに音階を上がる)、Mini Metro(盤のデータを音の高さ・定位に割り当てる)、Tenori-on(格子=音)、Koshi のチャイム(五音音階ならどの順でも濁らない)
- **検証方法**: ブラウザで同じ棒に4つ積み、鳴った正弦波の周波数を記録(392 / 440 / 494 / 587 を確認)。実機での試聴は未実施
- **結果**: (実機で試したあとに記入)
- **判断**: 盤と玉の差の大きさはユーザーから一任。はっきり聞き分けられる程度にした
- **次の課題**: 実機のスピーカーで、盤/玉の差・音階の上がり方・読み切りの揺れの強さを確かめる。リーチ以外の新しい場面(負け・引き分け専用など)は未検討

## 2026-10-08 既存最強AI(score4_AI)との対戦 1手1秒・100局

- **日付**: 2026-10-08
- **対象バージョン / commit**: main 14e506f の C++ エンジン(sym、定石つき)
- **仮説または目的**: requirements 5.1 の基準で現状の強さを測る
- **変更内容**: bench/(score4_AI のドライバ、開始局面50個、対戦場)を追加
- **検証方法**: `python3 bench/arena.py --ms 1000 -j 2`(50局面×先後、両者1スレッド)
- **結果**: 70勝30敗0分、得点率70.0%(95%区間 61.0〜79.0%)。うち5勝は score4_AI の反則(時間切れで打ち切った読みから埋まった棒を返す)。反則を除くと95局で68.4%。先手時74%・後手時66%。平均約51手、思考時間 A 平均653ms・最大1098ms / B 平均710ms・最大1130ms。所要27分
- **判断**: 1秒条件では合格ライン(60%)を超えている見込み。5秒条件は未計測
- **次の課題**: 5秒条件の100局(約2〜3時間)、改良(手の並べ方・評価関数・並列化)の効果測定

## 2026-10-08 書体の見比べページ(明朝・ゴシック・数字の3層)

- **日付**: 2026-10-08
- **対象バージョン / commit**: 14e506f の次(未コミット。ゲーム本体の書体は変更なし)
- **仮説または目的**: タイトルの個性と全体の磨き込み。共有メモ §9「物理世界は暖かい、非現実・意味の表現は冷たい」を文字にも当てはめる(タイトル・名前=明朝、画面の文字=静かなゴシック、数字・解析=細く桁がそろう欧文)。ロゴは書体と字間だけで作り、線を足す案はユーザー判断で不採用
- **変更内容**: `tools/font-lab.html` を追加。ホーム・対局中・決着と振り返りの見本に、明朝5案・ゴシック4案・数字5案を切り替えて当てる。タイトルの字間も調整できる
  - 参考: SEKIRO / Ghost of Tsushima(ロゴは個性、メニューは意図的に地味)、Monument Valley / Mini Metro(文字を減らし、色と配置で導く)、明朝に付属の欧文・数字は作りが粗いことが多い
- **検証方法**: 同じ端末で切り替えて比べる。実機でも確認する
- **結果**: ユーザーから「Claudeのおすすめでよい」。明朝=しっぽり明朝 B1(タイトルだけ 800、他は 600)、ゴシック=Zen 角ゴシック New のまま、数字=IBM Plex Mono(数字 0-9 の字形だけ読み込み、結果の手数・戦績・おすすめの棒・振り返りの手数・棋譜に適用)を index.html に組み込んだ。B1 はインク溜まりが「確かな物」の質感になり §7 の理想化された実物盤に合う。ゴシックは参考作品と同じく画面の文字を控えめに保つため据え置き
- **判断**: 使う文字だけ切り出して `fonts/` に同梱し、Google Fonts の読み込みをやめた(オフラインでも表示される)。`tools/subset_fonts.py` で作り直し、`--check` で index.html の字がすべて入っているか確かめる。合計約730KB(明朝3太さ 約550KB、ゴシック2太さ 約180KB、数字 4KB)。元のフォントは google/fonts の OFL 版、ライセンスは `fonts/OFL-*.txt`
- **次の課題**: 実機で見え方を確かめる。文言を足したら `tools/subset_fonts.py` を実行し直す
