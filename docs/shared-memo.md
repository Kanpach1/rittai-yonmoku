# 立体四目 開発共有メモ

この文書は、ユーザー・ChatGPT・Claude Codeでここまで合意した内容の共有用です。
新しい提案ではなく、現時点の判断を同期することが目的です。
Claude Codeは、ここに書かれていない仕様を勝手に補完・追加しないでください。

## 1. 開発体制

役割は以下で固定する。

### ユーザー

プロダクトオーナー。

* 実際に遊んだ感覚による最終判断
* 仕様の採否
* ゲームとして気持ちいいかの評価
* AI同士の意見が割れた場合の最終決定

### ChatGPT

設計・研究・レビュー担当。

* ゲームデザイン
* UX / UI
* 演出
* 音響
* AIアルゴリズム設計
* 要件整理
* Claude Code向け実装指示書
* 実装後レビュー
* ベンチマーク結果の解釈

### Claude Code

実装担当。

* 既存コード調査
* 指示された仕様の実装
* テスト
* ベンチマーク
* バグ修正
* 指示範囲内のリファクタリング

仕様を勝手に増やさない。

## 2. 指示の優先順位

1. ユーザーからの直接指示
2. 今回の実装指示書
3. `docs/requirements.md`
4. `docs/design.md`

実装指示書とrequirementsが明確に矛盾する場合は、勝手に解釈して進めず報告する。
結果が変わる仕様上の曖昧さは確認する。
既存コードや仕様から一意に判断できる単なる実装詳細は、自律的に処理してよい。

## 3. プロジェクトの二つの目標

このプロジェクトには二本の柱がある。

### 人間が遊ぶゲーム

目標：

立体四目そのものに没頭できる、最も静かで、最も深い対局環境を作る。

報酬・ガチャ・大量の称号などで遊ばせるのではない。
立体四目自体が面白いから、もう一局遊びたくなることを目指す。

### 研究・AI

目標：

立体四目を、人間が到達できない深さまで解析する最速・最強のエンジンを作る。

まず既存最強AIを超える高速・高性能AIを作る。
長期的には完全解析も目指す。

表側のゲームUIと研究環境は混ぜない。

理想：

裏側は異常に賢い。
表側は異常に静か。

## 4. 立体四目の根本的な面白さ

単なる「3Dで四つ並べるゲーム」とは捉えない。

重要なのは重力によって、

今はまだ置けない場所

が存在すること。

一手置くことで、

* 現在の場所を取る
* その真上を新しく合法手にする

という二つのことが同時に起こる。

さらに、その新しく使える場所は相手も利用できる。

したがって上級者になるほど、

どこへ置くか

ではなく、

誰に、どこを埋めさせるか

を見るようになる。

開発者向けの本質的な表現：

立体四目は、未来のマスの所有権を奪い合うゲームである。

別の表現：

まだ置けない勝ち筋を読み、相手にその足場を作らせるゲーム。

体験としては、

自分と相手がそれぞれ違う未来を見ながら、その未来を手番によって押し付け合うゲーム。

が近い。

## 5. 上達とは何か

上達の本質は数値や称号ではない。

盤上の情報量は同じなのに、意味として見えるものが増えること。

プレイヤーには、

* 最初：玉が見える
* 次：線が見える
* 次：決勝点が見える
* 次：まだ置けない決勝点が見える
* 次：そのマスを誰が解放するかが見える
* 最終的には相手が置かされる場所まで見える

という変化が起きる。

ゲーム側は、この発見を対局中に先回りして教えてはいけない。

## 6. 対局中の情報提示原則

固定原則：

見えるべき物体は見せる。
読むべき意味は見せない。

したがって通常対局中は、

* 決勝点
* 候補手
* 形勢
* 勝率
* 双決成立
* 強制勝ち
* 「もう詰んでいる」こと

などを表示しない。

プレイヤーが自分で気づく瞬間が、このゲームの重要な快感だから。

ただし知覚負けは減らす。
盤面そのものは現実より読みやすくしてよい。

## 7. ビジュアルの最上位原則

固定済み：

本物の立体四目を触る気持ちよさを、現実より読みやすく、現実には不可能なほど理解しやすくする。

方向性：

理想化された実物盤。

おおよそ

* リアル 70
* デジタル 30

程度。

完全な物理シミュレーションではなく、

物理法則ではなく物理感覚を守る。

## 8. 世界観

方向性：

現実と非現実の境界。

重要な表現：

物質は現実、空間は非現実。

または、

触れるものは現実。
そこにある場所だけが現実ではない。

盤・玉・柱・接触・重力は現実的。

背景空間には、

* 明確な壁
* 明確な床
* 宇宙
* 星
* 粒子
* 派手な霧

などを置かない。

暗い空間に、盤だけが極端に確かな物体として存在する。

非現実感は「何かを大量に足す」のではなく、

* 現実では不可能な読みやすさ
* 完璧すぎる光
* 少しだけ誇張された物理
* 意味が発生したときだけ現れるデジタル表現

によって作る。

## 9. 色彩方向

ゲーム空間はダーク基調。

ただし真っ黒なUIではなく、

暗い藍墨の空間に、暖かい実物盤が存在する

イメージ。

基本構成：

* 背景：ほぼ黒に見える藍墨
* 盤：暗く低彩度のウォールナット
* 柱：黒染め金属
* 玉1：朱
* 玉2：象牙
* デジタル表現：わずかに青みのある銀白

重要：

物理世界は暖かい。
非現実・意味の表現は冷たい。

金色を主要表現には使わない。
ネオンブルーにも寄せない。

例外：振り返りで表示中の局面の直前の一手を示すリングは、象牙の玉の上でも見えるよう明るい黄にする（ヒントの金とは区別する）。

色は装飾より、

物体と意味の種類を区別するもの

として扱う。

朱は暗すぎる深紅ではなく、暗い盤上でも識別できるやや橙寄りの朱を研究する。

象牙は純白にしない。

## 10. 盤の素材

### 盤

ウォールナット系。

木目は近くで見れば分かる程度。

派手な赤茶・オレンジにはしない。

### 柱

黒染め金属。

光る真鍮ではない。

真っ黒に潰さず、縁でわずかに冷たい反射を拾う。

### 玉

実在しそうな高密度樹脂のような質感。

* 朱：サテン寄り
* 象牙：少しマット

透明・ガラス・鏡面にはしない。

## 11. 演出の基本思想

通常時：

デフォルメされた現実の物理。

重要な瞬間：

デジタルな意味表現。

役割分担：

* 光 = 情報・意味
* 物理運動 = 重さ
* 音 = 時間と接触
* 触覚 = 衝撃
* 音楽 = 状態転換

通常着手で光を派手に使わない。

## 12. 一手のゲームフィール

一手は、

探す → 選ぶ → 予告 → 確定 → 落下 → 接触 → 静止

という流れ。

別の言い方：

考える時間は自由。
置く瞬間だけは最高に気持ちいい。

実物の、

16本から一本を選び、玉を棒へ通してストンと落とす

という地味な気持ちよさを、デジタルで増幅する。

## 13. 柱の当たり判定

現状の太い透明円柱への単純Raycastでは、重なったとき常に手前の柱が勝つため問題がある。

新しい考え方：

見た目のメッシュを正確に当てさせるのではなく、

どの棒の先端へ玉を通そうとしたかを推定する。

選択基準は棒の先端が主。

次の着地点はpickには使用しない。

優先度：

1. 棒の先端
2. 棒の上部
3. 棒全体

初期値として検討済み：

* 先端：30 CSS px
* 上部：24 CSS px
* 棒全体：16 CSS px
* 上部領域：上側35%

先端候補が存在すれば、手前の柱の胴体より奥の柱の先端を優先できる。

## 14. 柱選択中の挙動

pointerdownで柱を選択。

小さな指移動では候補を再評価してよい。

ただし境界で、

7 → 8 → 7 → 8

のようにガタつかせない。

切替ヒステリシスを使用。

初期案：

新しい候補が現在候補より約6px明確に近い場合のみ切り替える。

## 15. 着手と回転のジェスチャー

現在の方向：

* pointerdown：着手候補
* pointermove：小移動なら候補調整
* 約10 CSS px以上動いたら着手候補をキャンセルして回転モード
* 一度回転モードへ入ったら、そのpointer操作では着手に戻らない
* pointerup：タップ扱いなら着手

ドラッグは盤の回転。

柱選択と回転を同時に行わない。

## 16. ゴースト玉

重要な修正済み。

当たり判定の基準とゴースト玉の場所は分ける。

入力は棒の先端。
予告は次の着地点。

つまり、

* 柱を選ぶ基準：棒先端
* ゴースト玉：実際に次の玉が停止する位置

ゴースト玉を棒先端に浮かせない。

これは、

* 盤面が落ち着く
* 「どこへ置かれるか」が分かる
* 物質が空中に浮いているように見えない

ため。

確定すると、本物の玉は棒先端上から落下し、ゴースト位置へ収まる。

## 17. 盤面の柱番号

盤本体の番号は表示しない。棋譜および開発内部で必要な番号体系のみ維持する。通常プレイでは平面見取り図を提供しない。ただし3D表示不能環境のフォールバックとして平面表示を残す。

## 18. 着手物理

玉は棒先端上から重力で落ちる。

落下距離を感じられるようにする。

1段目までなら長く落ちる。
4段目なら短い。

すべて同じ時間にはしない。

着地時：

* 短いヒットストップ
* `コトッ`
* 接地影が締まる
* 微小な沈み込み
* 戻る
* 完全静止

跳ねさせない。

通常着手のヒットストップ初期検討値：

約30〜45ms。

最終値は実機で調整する。

## 19. 音響

基本：

接触は物理。
余韻はデジタル。

通常着手：

* 「コトッ」が主役
* デジタルな余韻は約0.3秒程度のごく薄いもの

起動・決着：

* 同じ音響素材の余韻を長くする
* 約1〜2秒まで使用可能

通常対局では常時BGMを主役にしない。

AI思考中も電子的な「計算中」SEなどは入れない。

## 20. AI思考中

盤は静か。

AIが考えている間に、

* 派手なアニメーション
* 計算中の電子音
* 意味のないエフェクト

を出さない。

AIが決めたら、

ストン → コトッ

と置く。

プレイヤーの着手演出中から内部ではAI思考を開始してよい。

これによって物理演出時間をAI計算時間の一部として使える。

## 21. 決着演出

勝ちをプレイヤーが自分で認識する時間を残す。

基本：

1. 最後の玉が落下
2. `コトッ`
3. 通常より少し長いヒットストップ
4. 約0.3〜0.5秒静止
5. 関係ない玉の存在感を少し下げる
6. 勝利4球を強調
7. 銀白の細い線が4球を一本の構造として貫く
8. 着手音の余韻が短い和音へ変化
9. 結果表示

勝利時だけ、

物理的な盤が内部に隠していた数学的構造を見せる

感覚を作る。

## 22. 対局中の「もう勝っている」局面

双決や強制勝ちが成立しても、

一切演出しない。

ここは絶対に重要。

まだ対局が続いているのに、

自分だけは結末を知っている

時間がこのゲームの大きな快感だから。

## 23. 振り返り

高度な分析画面を大量に見せることが目的ではない。

一局から一つだけ気づきを持ち帰らせる。

方向：

* 転機を一つ見せる
* その手を再生
* 必要な構造だけ可視化
* その局面からやり直せる

目的：

「あ、ここか。もう一回やろう」

を作ること。

## 24. 起動画面

起動演出は非常に重要。

方向：

最初のタップで、このゲームの象徴的な「ストン → コトッ」を体験させる。

ただし起動操作は対局上の正式な一手ではなく、

タイトル儀式

として扱う。

したがって画面のどこをタップしても開始してよい。

対局中の「棒先端を選択する」という操作規則とは別モード。

## 25. 起動演出の現時点案

配置：

1段目の対角線。

3玉を既に配置。
4玉目が入ると四目になる。

重力に反する浮遊配置は作らない。

待機中：

* 4玉目の本物の玉を棒先端に浮かせない
* 着地点にはゴースト玉を表示してよい

画面：

タップして始める

を表示。

タップ：

* 文字は即座に消える
* 本物の玉が棒先端上から落下開始
* 着地
* 短いヒットストップ
* 約0.3秒静止
* 細い銀白線
* 短い和音
* 「立体四目」
* 同じ盤のままホームへ

タップからホーム操作可能までは初期目標1.5〜2秒程度。

## 26. 起動と本番勝利演出の差

起動では、本番勝利演出をすべて見せない。

起動：

* ストン
* コトッ
* 一拍
* 細い勝利線
* 短い余韻

本番：

* より長いヒットストップ
* より深い静寂
* 周囲の玉の抑制
* 4球への集中
* 勝利線
* 完成した和音
* 結果

起動は本番の予告編。

## 27. 起動を繰り返したとき

「ストン → コトッ」は作品の署名として毎回残す方向。

ただし長い演出を強制しない。

2回目以降は、演出中の追加入力で残りを短縮できる方向を検討。

約0.3〜0.5秒でホームまで圧縮可能にする案。

## 28. 起動時の玉色

現時点の第一案：

朱で固定。

毎回ランダムにしない。

理由：

* 暗い空間で視線を集めやすい
* 胡桃・黒金属との組み合わせが良い
* 作品の署名として一定になる

ただし最終的な色調は実機で検証する。

## 29. ホーム画面

今回の起動演出実装では、

既存ホームUIを変更しない。

起動演出とホーム再設計を混ぜない。

起動で使った4玉はホーム移行時に消して、盤を空にする案が現時点で有力。

ホームUIの全面再設計は別タスク。

## 30. ホームの長期方向

将来的には、

メニュー画面ではなく、すでに盤の前に座っている状態

にしたい。

起動・ホーム・対局を別画面に見せず、

同じ盤の状態が連続して変化する

構造を目指す。

## 31. ゲーム名義 / レーベル

KKTを含む個人開発レーベルを作る方向には賛成。

候補：

* KKT Works
* KKT Interactive
* KKT Lab
* KKT Games

現時点では、

KKT Works

が最有力候補。

理由：

* ゲームだけに限定されない
* 最強AI・解析・教材・デジタル作品などにも広げられる
* 研究寄りすぎない
* 個人開発レーベルとして自然

ただし名称はまだ正式確定とは扱わない。

起動時に使う場合も、

小さく控えめに表示

する。

会社ロゴ演出を長く見せない。

## 32. 現在スコープ外のもの

現時点のrequirementsでは初心者向けチュートリアルはスコープ外。

以前議論した、

* 揃える
* 積む
* 立体斜め
* 相手に下を埋めさせる

という4問構成は将来案としてのみ保持。

今回勝手に追加しない。

## 33. AI対局について

AIの同一局面で毎回完全に同じ手を打つ問題は、将来的に品質改善対象。

方向：

* 上級・最強でも、ほぼ同価値の最善級手が複数存在する場合のみ少しばらけさせる
* 強さを落とすランダム化にはしない

ただし現在の起動演出タスクとは別。

## 34. ゲーム体験を判断する最上位基準

何か機能・演出を追加する場合、

技術的に高度か

ではなく、

実際に一局遊んだとき、立体四目そのものへの没頭が深まるか

で判断する。

機能量には価値を置かない。

最終的に残したい感覚：

もう一局だけ。

そして、

この盤を触っていたい。

## 35. 今後の演出判断の短い原則

一手には重さを。
思考には静けさを。
決着には間を。
再戦には速さを。

さらに、

通常時はデフォルメされた物理。
意味が生まれた瞬間だけデジタル。

そして、

考える時間は自由。
置く瞬間だけは最高に気持ちいい。
